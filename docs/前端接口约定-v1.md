# SPXH 前端接口约定 v1（冻结）

前端（spxh/web/static）与后端（spxh/api.py + spxh/web/server.py）之间**只通过下面这些 JSON 接口通信**。
任何一方改动都必须先改本文件。

约定：
- 所有接口都是 GET，查询参数用 path（工作区相对路径或绝对路径）、以及若干可选参数。
- 成功返回 200 + JSON；失败返回 4xx/5xx + {"error": "中文说明"}。
- 路径安全：服务端只允许访问工作区内的文件，越界返回 403。
- 数组统一用普通 JSON 数组；浮点保留足够精度（前端自己格式化）。
- 所有"估计量"对象结构统一为：
  {"value": 1234.5, "unit": "Hz", "confidence": 0.79, "method": "median(centroid,...)", "evidence": {...}}

## 0. GET /api/health

    {"ok": true, "version": "0.1.0", "estimator": "spxh-m1", "classifier": "spxh-rf-v1"}
    classifier 为 null 表示分类模型未训练。

# 附录：M3 解调接口（契约 v1.1 增补，冻结）

## 10. GET /api/demod?path=...&symbol_rate=&cfo=&modulation=&max_symbols=2000&trace_points=400

前端"解调"页只依赖这一个接口 + 已有的 /api/spectrum、/api/constellation。

    {
      "path": "data/demo/qpsk_snr+10.0_000.sigmf-meta",
      "modulation": "qpsk",
      "modulation_source": "classifier",          // classifier | provided | truth
      "symbol_rate": 999.97,
      "cfo_hz": 0.59,
      // 环路锁定状态：这是"能不能相信解调结果"的判据
      "lock": {
        "timing": true,
        "carrier": true,
        "timing_metric": 0.83,                    // 0~1，越接近 1 越好
        "carrier_metric": 0.91,
        "snr_db": 9.8,
        "locked_symbols": 2100
      },
      "evm_percent": 10.2,
      // 判决前的符号轨迹（最多 max_symbols 个）
      "symbols": {"count": 2100, "i": [...], "q": [...]},
      // 同步环路的观测量（降采样到 <= trace_points 点）——让分析员"看出来怎么回事"
      "traces": {
        "index": [0, 5, 10, ...],                 // 符号序号（降采样后）
        "timing_error": [...],                    // 定时误差检测器输出（归一化）
        "phase_error_rad": [...],                 // 载波相位误差
        "freq_estimate_hz": [...]                 // 载波环当前频率估计（相对 M1 粗估的增量）
      },
      // 解调出的比特：前 128 个给数组，另外给一段预览字符串
      "bits": {"count": 4200, "preview": "1011010011...", "head": [1,0,1,...]},
      // 有真值时给出误码统计；无真值时整个字段为 null
      "ber": {"bit_errors": 0, "compared_bits": 4200, "bit_error_rate": 0.0, "symbol_error_rate": 0.0},
      "llr": {"count": 4200, "mean_abs": 6.31, "min": -42.0, "max": 41.7, "sample": [6.3, -4.1, ...]},
      "warnings": ["..."]
    }

约定：
- 无 modulation 参数时，后端用 /api/classify 的结果；置信度低时 gate 会体现在 warnings 里。
- 所有数组长度必须与对应 count 一致；traces 三个数组等长。
- 数值不能出现 Infinity/NaN（用 null 或省略）。
- 出错仍然是 {"error": "中文说明"} + 4xx/5xx。

# 附录：M5 帧同步与载荷提取接口（契约 v1.3 增补，冻结）

## 12. GET /api/frame?path=...&modulation=&symbol_rate=&cfo=

前端"帧"页只依赖这一个接口（加上已有的 /api/demod 做星座与同步轨迹）。

    {
      "path": "data/demo/qpsk_snr+10.0_000.sigmf-meta",
      "modulation": "qpsk",
      "modulation_source": "classifier",          // classifier | provided | truth
      "symbol_rate": 999.97,
      "cfo_hz": 0.59,
      "sync": {
        "preamble": "barker13",
        "preamble_bits": "1111100110101",
        "correlation_peak": 0.86,                 // 归一化相关峰（0~1）
        "peak_to_sidelobe_db": 8.6,               // 峰显著性：峰值 / 全序列中位数的 dB 比（必然 >= 0）
        "frame_start_symbol": 0,                  // 第一帧起点（符号序号，可为小数）
        "frame_start_sample": 124,                // 对应到原始采样点
        "ambiguity_rotation_deg": 90.0,           // **由前导解出的相位模糊**（不再靠真值搜索）
        "locked": true,
        // 逐符号的滑动相关幅度（降采样到 <= 400 点），供画"相关峰"图
        "correlation": {"index": [0,1,2,...], "value": [0.02, 0.81, ...], "stride": 1}
      },
      "frames": [
        {
          "index": 0,
          "start_symbol": 0,
          "start_bit": 0,
          "preamble_ok": true,                    // 13 位 Barker 逐位核对
          "header": {
            "payload_len": 128,
            "modulation": "qpsk",
            "fec": "none",
            "interleave": false,
            "header_hex": "0000008001..."
          },
          "crc": {"expected": "0x1A2B", "computed": "0x1A2B", "ok": true},
          "payload": {
            "bytes": 128,
            "hex": "48656C6C6F...",               // 最多前 256 字节
            "ascii": "Hello, SPXH!...",           // 不可打印字符用 .
            "head": [72, 101, 108, ...]           // 前 32 字节
          },
          "bit_errors_vs_truth": 0                // 有真值时给出；无真值为 null
        }
      ],
      "summary": {
        "frames": 4,
        "frames_crc_ok": 4,
        "payload_bytes_total": 512,
        "payload_bytes_exact": 512,               // 与真值逐字节一致的数量（无真值时为 null）
        "all_ok": true
      },
      "warnings": []
    }

约定：
- 无 modulation 参数时后端用分类结果，并在 warnings 里说明来源。
- **peak_to_sidelobe_db 的真实口径**是"峰值 / 全序列中位数的 dB 比"（峰显著性），必然 >= 0；
  不是"主瓣/最大旁瓣"—— Barker 的低旁瓣只对它自己的非周期自相关成立，埋在随机载荷里时
  别处凑出的相关值经常超过真峰（实测出现过 -0.17 dB，负数正说明旧口径不成立）。
  相关证据另在 evidence.peak_percentile（峰值在整条相关序列里的分位）与 evidence.peak_to_median_db 里。
- **locked 判据**：correlation_peak >= 0.25 且至少解析出 1 帧。相关峰很高但一帧都解析不出来时
  仍然是"未锁定"（例如纯噪声里的偶然高峰）。
- 契约外但会下发的诊断字段：frames[].reason / resync_shift_bits、summary.candidates_failed /
  truth_frame_offset、evidence.*（前端可以忽略）。
- 数值禁止 NaN/Infinity；无真值时 bit_errors_vs_truth / payload_bytes_exact 为 null。
- 出错仍是 {"error": "中文说明"} + 4xx/5xx。

# 附录：M8 谱相关（SSCA）接口（契约 v1.4 增补，冻结）

## 13. GET /api/ssca?path=...&nfft=256&max_points=160&alpha_max_factor=2.0

谱相关函数（SSCA 双频平面）：横轴是频移 f，纵轴是循环频率 α，能量峰落在
(f=载频偏移, α=符号速率及其谐波) 上 —— 这是"可解释性"最直接的证据面板。

    {
      "path": "data/demo/qpsk_snr+10.0_000.sigmf-meta",
      "sample_rate": 8000.0,
      "symbol_rate": 999.97,
      "nfft": 256,
      "freqs": [-3000.0, ..., 3000.0],        // 频移轴 f 的**完整**刻度 (Hz)，长度 F=256
      "alphas": [-2187.5, ..., 2187.5],       // 循环频率轴 α 的**完整**刻度 (Hz)，长度 A（含 0，可正可负）
      // 剖面用的是完整轴；热图为了传输量会降采样，**它有自己的轴**：
      "surface_alphas": [...],                // 长度 = surface_db 行数（<= max_points）
      "surface_freqs":  [...],                // 长度 = surface_db 每行长度（<= max_points）
      "surface_db": [[...], ...],             // A' 行 x F' 列（A'<=A, F'<=F），dB，峰值归一到 0 dB
      "min_db": -55.0, "max_db": 0.0,         // 色标范围（前端按此裁剪）
      "peaks": [                              // 前 8 个显著局部峰（已做非极大抑制）
        {"alpha_hz": 999.9, "freq_hz": 37.2, "level_db": -1.2}
      ],
      "alpha_profile": {"alpha_hz": [...], "level_db": [...]},   // 对 f 取最大值
      "freq_profile":  {"freq_hz":  [...], "level_db": [...]},   // 对 α 取最大值
      "features": {
        "symbol_rate_hz": 999.9,              // α 轴（>0 侧）最强峰：**精确**到频率分辨 bin
        "cfo_hz": 37.2,                       // α!=0 脊线在 f 轴上的位置（**脊线估计**）
        "cfo_ridge_hz": 37.2,                 // 同上，显式命名，避免与 M1 的精确估计混淆
        "note": "α 轴峰 = 符号速率及其谐波；cfo_hz 是 α!=0 脊线位置，分辨率 fs/nfft，"
                "只作解释用 —— 精确载频/符号速率看下面对照的 M1 估计"
      },
      "estimate": {                            // 契约外便利字段：M1 参数估计（精确值，供并排对照）
        "symbol_rate_hz": 1000.086, "cfo_hz": 3.86, "snr_db": 9.76
      },
      "warnings": []
    }

约定（重要，前端必须按这条解析）：
- **surface_db 的坐标是 surface_alphas x surface_freqs**（heatmap 的 A' x F'），
  它可能被降采样（默认 max_points=160，实测 F'=nfft/2=128、A'=71）；
- **freq_profile / alpha_profile 用的是完整轴** freqs / alphas，长度分别是 F 与 A；
  三者不要混用（前端曾经用 freqs 去索引热图列，把有效点错报成 null）。
- α 轴是对称的（含 0，可为负）；符号速率特征取 α>0 侧的最强峰。
- 数值禁止 NaN/Infinity；surface_db 允许用 null 表示无效点（前端要逐点容错）。
- 出错仍是 {"error": "中文"} + 4xx/5xx。

## 14. 前端本轮的两个硬要求（M8）

**(A) 所有图表都要能"鼠标放大/拖动"**（这是本轮的验收项，不是加分项）：
- 滚轮缩放（以鼠标位置为锚点）、按住拖动平移、双击/按钮复位；
- 频谱/PSD、瀑布图（频-时二维）、星座图、解调同步轨迹、译码 BER 曲线、帧相关峰、SSCA 热图 **全部**覆盖；
- 对数纵轴（BER、PSD）缩放要按对数坐标缩放，不能线性拉伸；
- 缩放状态在数据刷新后重置，并且要显示"当前视图范围"（轴标签/角标）；
- 不能因为缩放把交互搞崩：极端缩放要钳制（最小 8 个数据点跨度 / 最大不超过原始范围）。

**(B) 新增"谱相关"（SSCA）面板**：热图 + α 剖面 + f 剖面 + 峰值表 + 特征读数（符号速率/载频偏移），
数据来自 /api/ssca（第 13 节）。

# 附录：M9 帧头 CRC / 盲长度恢复 / 报告接口（契约 v1.5 增补，冻结）

## 15. /api/frame 的字段增补（帧头 CRC-8 与盲长度恢复）

帧头从 4 字节扩到 **5 字节**：第 5 字节 = 前 4 字节的 CRC-8（poly 0x07，初值 0）。
/api/frame 的响应新增：

    {
      "sync": {
        ...,
        "blind": {                                  // 只在 blind=1 时出现（否则为 null）
          "enabled": true,
          "header_crc_ok": false,                   // 收到的帧头 CRC-8 是否通过（true=没错，无需恢复）
          "length_recovered": true,                 // 载荷长度是否被盲恢复出来
          "hypotheses_tried": 1280,                 // 试过的 (编码, 交织, 长度) 假设数
          "repaired_header": {"payload_len": 60, "fec": "ccsds", "interleave": false},
          "frames_header_crc_ok": 6,                // 帧头 CRC 通过的帧数
          "frames_with_header_crc": 7               // 带帧头 CRC 字段的帧数（旧格式数据为 0）
        }
      },
      "frames": [
        {
          ...,
          "header": {
            ...,
            "header_crc8": "0x9C",                  // 收到的第 5 字节
            "header_crc_ok": true,                  // 帧头自校验
            "crc8_expected": "0x9C"
          }
        }
      ]
    }

约定：
- fec=none 且旧数据：帧头 CRC 字段不存在时，前端按"未知"显示（不要显示成"失败"）。
- 帧头 CRC-8 不通过时，帧仍然会被解析（尽力而为），但 header.header_crc_ok=false 且进 warnings。

## 16. GET /api/narrate?path=...&provider=offline|auto|&max_tokens=800

**LLM 分析报告**：把整条链路的**结构化证据**（M1 估计、M2 分类与门控、M5 帧同步/CRC、
M7 盲识别、M8 谱相关峰）交给 LLM 生成一段分析师视角的中文报告；没有配 LLM 时走**离线确定性渲染**，
两种模式的输出结构完全一致，且都会回传喂给模型的提示词，便于审计。

    {
      "path": "data/demo/qpsk_snr+10.0_000.sigmf-meta",
      "generated_at": "2026-10-05T19:30:00",
      "mode": "offline",                    // offline | llm
      "model": "offline-rule-based",        // 或真实模型名
      "headline": "QPSK，Es/N0 约 9.8 dB，符号速率 1000.0 Hz，帧同步锁定（6 帧/2 帧 CRC 通过）",
      "confidence": 0.72,                   // 0~1：由各环节置信度/门控/CRC 通过率合成
      "sections": [
        {
          "id": "signal", "title": "信号与参数",
          "text": "……中文分析……",
          "evidence": [ {"key": "snr_db", "value": 9.76, "unit": "dB", "source": "M1", "confidence": 0.9} ]
        }
      ],
      "uncertainties": ["低信噪比下符号速率置信度偏低（0.00）"],
      "next_actions": ["换用 30 dB 案例复核", "打开盲编码识别重试"],
      "prompt_preview": "……实际发出去的提示词（已截断）……",
      "warnings": []
    }

约定：
- mode=offline 时不联网、不读任何密钥，输出必须是确定性的（同样输入同样输出）。
- provider=auto 且环境变量 SPXH_LLM_BASE_URL / SPXH_LLM_API_KEY / SPXH_LLM_MODEL 齐备才走 llm，否则 offline。
- LLM 调用失败**不报 5xx**：降级为 offline 并在 warnings 里写明原因（分析平台不能因为 key 失效就不可用）。
- sections[].evidence 必须是**来自管线真实计算**的值，不许 LLM 编；离线模式直接用结构化字段渲染。

### 17.2 POST /api/llm/config   （JSON body，只提交要改的字段）

    body: {"enabled": true, "base_url": "http://127.0.0.1:11434/v1", "api_key": "sk-xxx",
           "model": "qwen2.5:7b", "temperature": 0.3, "max_tokens": 800, "timeout_s": 60,
           "clear_api_key": false}
    -> 200 返回与 17.1 完全相同的结构（脱敏）

- 保存是原子的（临时文件 + 替换），写失败时返回 500 {"error": ...} 且不破坏原文件。

### 17.3.1 base_url 归一化（v1.6 修订）

用户最常见的配置错误是把**完整接口地址**粘进 Base URL。后端现在自动去掉末尾的
`/chat/completions`、`/completions`、`/models` 与多余斜杠后再保存，
所以 `https://api.deepseek.com/chat/completions` 与 `https://api.deepseek.com/v1` 都能用。
**前端保存成功后要用响应里的值回填表单**（否则界面上还是归一化前的写法）。

### 17.3.2 test 响应新增诊断字段（v1.6 修订）

    "checked": {..., "chat_url": "https://api.deepseek.com/chat/completions",
                     "models_url": "https://api.deepseek.com/models"},
    "hint": "该服务商可用模型：deepseek-chat、deepseek-reasoner"   // 可能为空字符串

- `checked.chat_url` = **实际请求的地址**（Base URL 写错时的第一诊断依据）；
- `hint` 给"模型名写错/可用模型清单"这类可操作提示；
- 错误文案已带常见原因：400（模型名/JSON 模式/参数）、401（密钥）、402（余额）、404（地址或模型不存在，提示检查是否多写 /chat/completions）、429（限流）。

### 17.6 服务商预设（v1.6 新增）

GET /api/llm/config 额外返回 `presets`，供前端一键填充：

    "presets": [
      {"id":"deepseek","label":"DeepSeek","base_url":"https://api.deepseek.com","model":"deepseek-chat",
       "notes":"官方兼容 OpenAI 协议；base_url 写 https://api.deepseek.com（或 .../v1）。模型：deepseek-chat（对话）或 deepseek-reasoner（推理，不支持 JSON 模式，平台会自动降级重试）"},

      {"id":"ollama","label":"本地 Ollama","base_url":"http://127.0.0.1:11434/v1","model":"qwen2.5:7b","notes":"..."},
      {"id":"custom","label":"自定义（OpenAI 兼容）","base_url":"","model":"","notes":"..."}
    ]

另：`config_path` 现在回**相对路径**（`config_path_abs` 给绝对路径）。

**平台侧对 JSON 模式的兜底**：调用 /chat/completions 时优先带 `response_format=json_object`；

### 17.5 /api/narrate 的行为随之明确

### 18.2.1 v1.8 补充：真机多回的字段（前端可忽略，向后兼容）

- `GET /api/agent/tools` 另回 `hard_limits`（max_rounds 12 / max_tool_calls 24 / timeout_s 300 的硬上限）；
- `GET /api/auth/status` 另回 `host`（实际监听地址）；
- `POST /api/agent/run` 的工具调用条目另含 `error`（失败原因，成功时空串）与 `extra`（工具的补充字段）；
- `grounding` 另含 `allowed_numbers`（白名单里的数字个数）、`unsupported[].section`（哪个段落里出现的）；
- 离线模式（`mode="offline"`）的 `final` 是由确定性渲染器产出的，结构与 LLM 模式一致；
  若某个 section 的证据为空数组，说明该环节没有可用证据（前端按"无证据"占位即可）。

硬约定：
- **有界**：`max_rounds`（默认 6，上限 12）、`max_tool_calls`（默认 12）、墙钟超时（默认 120 s，上限 300）
  任一触顶即停，`stop_reason` 如实回报；**同一个工具+同一参数重复调用会被拒绝**并记进 warnings。
- 工具结果**结构化**返回（summary 给人看、evidence 给模型与 grounding 用），单个结果截断到 4 KB。
- 工具调用失败不影响整体：如实记录 `ok=false` + 中文原因，循环继续或按模型决定停止。
- 没有可用 LLM 时走**离线确定性代理**（固定计划：analyze → classify → frame → ssca），
  `mode="offline"`、`stop_reason="no_llm"`，结构完全一致（面板永远有东西看）。

## 19. 访问令牌（当工作台不再只服务本机时）

    GET /api/auth/status -> {"auth_required": false, "loopback_only": true,
                             "hint": "当前仅监听回环地址且未设置令牌：本机单人使用不需要令牌"}

约定：
- **默认（只监听 127.0.0.1 且未设置令牌）：不鉴权** —— 本机单人使用不该被令牌烦；
- 一旦 `--token <值>` / `--token auto`（自动生成并打印）**或**监听非回环地址，则
  **写接口与配置接口必须带** `Authorization: Bearer <token>`（也接受 `X-SPXH-Token`）；
- 不通过 -> `401 {"error":"需要访问令牌（401）"}`；`GET /api/health` 永远开放（探活用）；
- 前端把令牌存在 localStorage，并在请求头里带上（`?mock=1` 不受影响）。

## 20. 密钥落盘加密（Windows DPAPI）

- Windows 上密钥用 **DPAPI（CryptProtectData，绑定当前用户）** 加密后存 `api_key_enc`；
  配置文件里**不再出现明文**；
- 非 Windows 或 DPAPI 不可用：退回明文存储并在配置视图里标 `api_key_protected: false` + warning；
- 接口行为不变：仍然只回显 `api_key_hint`；`GET /api/llm/config` 新增
  `api_key_protected`（true=已加密落盘 / false=明文或未配置）。

## 9. 前端必须覆盖的信息（M1/M2 部分）
