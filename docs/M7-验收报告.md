# M7 验收报告：平滑端到端曲线 / 盲编码识别 / RS 擦除译码

日期：2026-10-04  链路标记：spxh-m7  版本：0.1.0

## 1. 范围

M7 把 M6 留下的三件事做完：

1. **平滑的端到端曲线**：M6 每点只跑 4 帧，CRC 通过率的量化步长是 25%，门限是插值出来的、抖动大
   （CCSDS 在两轮里从 5.8 dB 跳到 9.6 dB）。现在每点 24 帧、12 个信噪比点。
2. **盲编码识别**：帧头里的 fec/interleave 字段自己被打错时，不靠它也能把编码认出来。
3. **RS 擦除译码**：已知不可信位置时，纠错能力从 t 个符号翻倍到 2t = nsym 个符号。

## 3. 结果二：盲编码识别（帧头 fec/interleave 字段被打成 0，谎报"无编码"）

| 真编码 | 按帧头声明解 | 盲搜索 | 命中假设 | 载荷 |
|---|---|---|---|---|
| conv | 失败（预期） | 恢复 | conv | 一致 |
| rs | 失败（预期） | 恢复 | rs | 一致 |
| ccsds | 失败（预期） | 恢复 | ccsds | 一致 |
| ldpc | 失败（预期） | 恢复 | ldpc | 一致 |

做法不是"猜"，而是**假设 + 校验**：对每个 (编码, 交织) 假设，**把帧头里的 fec/interleave 位
按假设重写**，再算 CRC —— 只有假设正确时 CRC 才会对上。

这里有个关键点值得记下来：如果直接用**收到的（被打错的）帧头字节**算 CRC，那么无论编码假设多正确，
CRC 都永远对不上（因为发射端的 CRC 是用**原始帧头**算的）。也就是说"盲识别"必须同时修正帧头字段，
否则做不出来。

## 4. 结果三：RS 擦除译码（RS(76,60)，t=8，2t=16）

在已编码载荷里打一段连续字节错误：

| 字节突发 | 无擦除信息 | 已知位置（擦除） | 按置信度自适应挑擦除 |
|---|---|---|---|
| 8（= t） | 通过 | 通过 | 通过 |
| 9 | **失败** | **通过** | **通过** |
| 12 | **失败** | **通过** | **通过** |
| 16（= 2t） | **失败** | **通过** | **通过** |
| 17（> 2t） | 失败 | **失败** | 失败 |

* 未知位置最多纠 t=8 个符号；**已知位置最多纠 16 个** —— 擦除译码把能力翻倍，9~16 这一档就是它的价值。
* "按置信度自适应挑擦除"用"平均 |LLR| < 1 的字节全部标为擦除（上限 16）"来选，不依赖任何真值。
  第一版写的是"固定挑 12 个最不可信的字节"，在 16 字节突发时漏掉真坏位置而失败 —— 改成自适应门限后通过。
* 17 个擦除超出 2t：**如实报不可纠**，绝不猜。
* 本实现只做**纯擦除**（位置已知、无额外未知错误）。若擦除位置标得不够全、还有未知错误，
  会明确返回不可纠而不是给出可疑结果（已有单测覆盖）。

## 5. M7 期间发现并修复的问题

1. **CRC 覆盖被篡改帧头 -> 盲识别必须先修帧头**：见第 3 节。这也是"帧头留在编码之外"这个设计的
   代价：帧头自己错了，只能靠"假设 + 校验"而不是靠译码纠错来发现。
2. **擦除选择不能固定个数**：固定挑 12 个在 16 字节突发下必败；改成置信度门限自适应后通过。
3. **候选峰预算**（M6 遗留）：编码帧更长、前导相对更短，弱信噪比下前 12 个候选峰可能全是虚警，
   把预算提到 40、阈值降到 0.35 倍峰值后，8 dB 的编码案例从 0 帧变成能解析。
4. **CCSDS 任意长度**：CRC 进编码后信息多了 2 字节，"深度 5 整除"的约束会挡住很多长度，
   改成"在信息尾部补零到深度倍数"，收发两端算法一致、任意长度可用。

## 6. 已知局限

- **擦除译码只支持纯擦除**：误差 + 擦除的联合译码（Forney 伴随式 + 修正 BM）没做；
  当前遇到"擦除不全 + 未知错误"时老实报不可纠。要做完整版，下一步接 Forney 伴随式。
- **盲识别依赖帧头的 payload_len**：长度字段被打错时无法盲恢复（假设空间变成"长度 x 编码"的二维）。
  实用做法是给帧头自身加一个短 CRC，下一步可做。
- **低信噪比下帧同步先掉链子**：5~8 dB 只能解析出 9~17/24 帧，所以那几行的通过率分母偏小；
  要更干净的曲线，需要更强的帧同步（更长前导或相关积累）。
- **曲线仍有 ±4% 涨落**：24 帧/点的量化步长；要更平滑就继续加帧数（成本线性增长）。

## 7. 快速使用

    # 平滑曲线（约 3.5 分钟）
    python scripts/check_m7.py --part curves

    # 盲编码识别 / 擦除译码（秒级）
    python scripts/check_m7.py --part blind
    python scripts/check_m7.py --part erasure

    # 命令行：盲模式解帧（帧头 fec 字段不可信时）
    python -m spxh frame data/demo/qpsk_ccsds_snr+8.0_000.sigmf-meta --blind

    # 接口：/api/frame?path=...&blind=1
