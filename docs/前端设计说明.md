# 前端设计说明 — SPXH 射频信号分析工作台

- 作用域：只涉及 spxh/web/static/（index.html / style.css / app.js / mock/*.json）与本文档，未改动任何 Python 代码。
- 契约依据：docs/前端接口约定-v1.md（冻结）。前端严格使用契约字段名，不做重命名或推断性改写。
- 技术约束：单页应用、无构建步骤、纯 HTML + CSS + 原生 JS(ES2020)、无任何 CDN / web font / 外部图标，完全离线可用。

## 1. 设计取向（一句话）

**暗色 SDR 仪器控制台：深灰蓝底 + 单一青绿强调色 + 等宽数据字体 + 低对比细网格，高信息密度、零装饰性动效。**

三档自定标：版面变化度 2（仪器面板要可预期，不用非对称花活）、动效强度 1（只有 120ms 的状态切换）、信息密度 8（这是数据工具，不是落地页）。

## 2. 配色与字体选择理由

| 类别 | 取值 | 理由 |
| --- | --- | --- |
| 底色四级 | #0a0e13 / #0e141b / #121a23 / #18222d | 用亮度差表达层级，全站无一处 box-shadow、无渐变面板，避免"阴影堆叠"式的假深度 |
| 强调色（唯一） | 青绿 #2ed3b7 | 频谱仪上"信号"惯用的青绿语义；只用于当前选中项、PSD 主折线、关键数值、焦点环 |
| 语义色 | 绿 #57c98a / 琥珀 #e0a23a / 红 #e2605f | 只用于置信度徽标、门控状态、告警等级、错误条。与强调色语义分离：强调色=选中的/信号，语义色=判断的结论 |
| 线 | #1d2833 / #28353f / #38485a | 网格与分隔线刻意低对比，且只做 1px，不与数据 争视觉权重 |
| 数据字体 | ui-monospace, "Cascadia Mono", Consolas, "Liberation Mono", Menlo, monospace | 23 维特征表、误差列必须按位对齐；等宽 + font-variant-numeric: tabular-nums 保证小数点成列 |
| 界面字体 | system-ui, -apple-system, "Segoe UI", "Microsoft YaHei", "PingFang SC" | 面板标题/按钮用无衬线，和等宽数据形成两级层次；纯系统字体，零网络请求 |

全站唯一的彩色渐变是瀑布热图色带（深蓝→青绿→琥珀），它是数据编码而非装饰。明确不采用：AI 紫渐变、玻璃拟态模糊、居中大标题 hero、三张等宽圆角营销卡片、无意义循环动画。参数估计的三张卡片按仪器面板做——左侧 2px 强调竖线、2px 圆角、无阴影、无渐变。

置信度徽标阈值：>= 0.7 高（绿）、>= 0.4 中（琥珀）、否则 低（红）、无值（虚线灰）。

## 3. 布局与响应式

- 结构：顶栏（品牌 + 估计器版本 + 分类器版本 + 数据源）→ 错误条（有错时才出现）→ 主壳（左栏 + 工作区）→ 底部状态栏（当前路径 / 当前视图 / 更新时间 / 数据源）。
- 左栏：数据源面板（手输路径 + 加载、案例目录 + 刷新）+ 案例列表（顶部过滤框，列表独立滚动）。
- 工作区：概览条（当前路径 / 采样率 / 采样点 / 时长 / 峰值 / 峰值 SNR / 占用带宽 / 噪声底）→ 告警条 → 标签栏（sticky）→ 五个面板（频谱/瀑布、参数估计、特征、识别、解调）。

断点：

| 宽度 | 行为 |
| --- | --- |
| >= 1200px | 左栏 296px + 工作区 |
| 900–1199px | 左栏 252px，概览 3 列 |
| < 900px | 上下堆叠（左栏在上，案例列表限高 38vh），概览 2 列 |
| < 640px | 概览单列，图高下调（PSD 226px / 瀑布 250px / 星座 290px），隐藏次要 chip |

Canvas：全部按 devicePixelRatio 缩放（canvas.width = 逻辑宽 * dpr，ctx.setTransform(dpr,0,0,dpr,0,0)），由 ResizeObserver（工作区 + 左栏）与 window.resize 触发，经 requestAnimationFrame 合并后重绘当前可见标签页的图；面板隐藏时尺寸为 0，绘图函数提前 return，不做无效重绘。

交互反馈一律 <= 120ms（transition 120ms linear），仅用于背景/边框/颜色/进度条宽度等状态切换，无循环动画；@media (prefers-reduced-motion: reduce) 下把过渡与动画时长压到 0。

## 4. v1 的四个标签页各自展示什么

（M3 新增的第五个标签页「解调」见 §10。）

### 4.1 频谱 / 瀑布

工具条：nperseg(256/512/1024/2048/4096)、nfft(auto/2048/4096/8192/16384)、points(600/1200/2000/4000)、幅度 dB·线性分段开关、残余曲线开关、重绘按钮。nperseg/nfft/points 变更会重新请求 /api/spectrum；瀑布固定用 min(nperseg, 512) 与 max_frames=400、max_bins=192（时间分辨率优先）。

PSD 图（Canvas）依次绘制：占用带宽阴影（occupied.f_low..f_high）+ 两条边界竖线 → 细网格与频率/幅度刻度 → 噪声底虚线（noise_floor_db，并直接标注数值）→ 残余曲线（residual_db 映射到右轴 -60..0 dB，琥珀点线，右轴标 0 与 -60）→ PSD 折线 + 极低透明度面积（0.055）→ 峰值圆点（peak.frequency_hz 最近点）→ 两条竖线：青绿虚线=估计载频（cfo.value）、琥珀实线=真值（cfo_true，为 null 时不画）→ 左上角幅度标注"PSD (dB)"或"功率 (线性)"。线性模式下先把 dB 转成 10^(dB/10) 再线性缩放，噪声底与真值线同步换算。图例按数据自适应（无真值时不出现"真值 CFO"项）。

瀑布图（Canvas）：magnitude_db 经 256 级 LUT 上色，第 0 行=最低频，绘制时翻转到底部；右侧 11px 色标带 + max/mid/min dB 三个标注；X 轴时间(s)、Y 轴频率(Hz)；标题右侧显示 shape、dB 范围与总时长。

### 4.2 参数估计

- 三张卡片：载频 CFO / 符号速率 / SNR。每张包含：大字号数值 + 单位（来自 Estimate.unit）+ 置信度徽标 + method 字符串 + 口径说明 + 证据（可折叠 details，JSON 语法高亮）+ 对账行（真值 / 绝对误差 / 相对误差）。没有 comparison 时卡片明确显示"无真值：不做对账"。
- 对账表：列为 估计量 / 估计值 / 真值 / 绝对误差 / 相对误差，行取载频、符号速率、SNR；下方补 sps 真值与估计、analyze 的 sps。
- 分析元数据：sample_rate、num_samples、duration_s、noise_floor_psd、total_power、peak.frequency_hz、peak.snr_db、occupied.bandwidth、occupied.center、occupied.captured_fraction、sps，并把后端 meta.* 的全部键原样展开（不丢信息）。

### 4.3 特征

- 顶部摘要 chip：维度（23 维 / 5 域）、symbol_rate、cfo_hz、snr_db、是否含 values_by_name。
- 5 个域分组卡，域名为中文：累积量 / 频谱 / 时频 / 星座 / 循环平稳。每维一行三列：名称（等宽，悬停提示 index）+ 数值（等宽、tabular-nums、统一 4 位小数对齐，超出 1e5 或小于 1e-4 时改用科学计数法）+ 条形图（按组内最大绝对值归一，负数用琥珀）。域的顺序固定为契约分组顺序；接口若给出未知域名则排在最后并直接显示原名。
- 星座图（Canvas）：/api/constellation 的 i/q 散点、过原点网格、等比例坐标、幅度归一（max*1.12），标题右侧标注符号数 / EVM / 参数来源(estimated 或 provided) / 使用的 Rs 与 CFO。把它放在特征页而不是单开标签页，是因为契约第 9 节没把它列入必覆盖面板，而需求明确要求四个标签页。

### 4.4 识别

- 结论块：大字号调制名（统一大写；gate=reject 且 modulation 为空时显示"未识别"并用报错色）+ gate 徽标（ml=绿"门控 ML 通过" / fallback=琥珀"门控 物理回退" / reject=红"门控 拒识"）+ 置信度 + OOD（分数与是否离群）+ 校准状态 + 副标题（gate / threshold / 是否校准）。
- 调制概率：按概率降序，条形长度=概率值，首位用强调色，右侧 4 位小数，另显示门控阈值及其含义。
- 门控与判据：gate、threshold、confidence、calibrated、ood.method、ood.score、ood.is_outlier，以及响应 features.* 的全部键。
- 物理规则回退：physical.modulation + physical.reason，并附原始 JSON。physical 为 null 时区分两种情形：门控要求回退却没有规则命中（警示文案）与本次未触发（中性文案）。

## 5. 状态与错误处理

- **错误条**（需求硬性项）：任何非 2xx、网络失败、或响应不是合法 JSON，都会在页面顶部生成红色错误条，逐条写明 **接口名 + HTTP 状态（或"网络"）+ 后端 error 文案 + 请求 URL + 时间**；相同错误去重并累加计数；可单条清除或全部清除。相应面板的空态同时写"XX 加载失败（见顶部错误条）"，绝不静默失败。
- **加载态**：状态栏左端变青绿并显示"加载中…"，各面板空态显示"加载中…"，案例计数 chip 显示"加载中"。
- **空态**：未选路径 → "等待数据：请在左侧选择案例或输入路径"；目录内无案例 → "目录内没有可用案例"；过滤无命中 → "没有匹配「x」的案例"；接口字段缺失 → 明确写出缺什么（例如"特征接口返回了 names 但没有 values"、"响应中没有 probabilities"）。
- **无真值态**：案例卡打"无真值"虚线标签；对账表与估计卡都给出显式中文文案（"该案例不含真值（truth），无法对账" / "无真值：不做对账"），不留空白。
- **告警清单**：全局告警条按来源（analyze / features / classify）与等级着色——绿=无告警、琥珀=置信度低/方差大/概率接近/OOD 离群、红=gate 拒识或失败异常。干净的有真值案例会显示绿色"无告警"，使绿色状态可见。

## 6. 实现要点

- 无构建、无 CDN：只有 index.html / style.css / app.js 三个静态文件，app.js 为 IIFE + 'use strict'，不使用模板字符串（便于嵌入与静态扫描）。
- 请求代际：dataGen（数据）与 casesGen（案例列表）两个计数器，切换路径/目录后旧响应直接丢弃，避免快速点击导致的串台。
- URL 同步：?path=（点击案例或手输都写入）、?dir=、?tab=、?mock=1；使用 history.pushState/replaceState 与 popstate，刷新与前进后退都保持状态。
- mock 模式：?mock=1 时所有请求改为 /static/mock/ + slug + .endpoint.json（health.json / cases.json 除外），并注入 150ms 人为延迟以便观察加载态；slug 由 path 去掉 .sigmf-meta/.sigmf-data/.truth.npz/.npz/.wav/.raw 等后缀得到，因此 URL 里带 +10.0_000 这类字符也能正确映射。
- 契约兼容：comparison 同时兼容契约文档中的精简键（cfo_error_hz / symbol_rate_rel_error / es_n0_error_db）与后端 analyze.py 实际产出的完整键（cfo_true_hz / symbol_rate_true_hz / es_n0_true_db 等），任一形态都能算出绝对误差与相对误差。
- 特征目录：优先使用接口下发的 names / groups / values_by_name；仅在缺失时回退到内置 23 维兜底目录（域划分严格按契约的 4/5/3/5/6）。
- 无障碍：tablist/tab/tabpanel 角色与 aria-selected/aria-controls，支持左右方向键与 Home/End 切换标签页；跳转主区域链接；焦点环使用强调色；prefers-reduced-motion 生效。

### 自查中发现并修复的 3 个真实缺陷

1. **未定义函数导致整页不可用**：renderAll() 调用了未定义的 renderSpectrum()，任何数据加载完成都会抛 ReferenceError。已改为 renderSpectrumLegend() + redrawVisible()。
2. **标签页面板可见性判断写反**：原为 show(panel, panel.dataset.panel !== tab)，结果是"当前标签页被隐藏、其余三个全部显示"，在真实浏览器里主图会是空白。已改为 ===。
3. **瀑布图数据到达后不重绘**：renderAll() 只驱动了频谱绘制，瀑布要等用户切换标签页才出现。已把频谱/瀑布/星座的绘制统一收敛到 redrawVisible()，由 renderAll() 与 activateTab() 共同驱动。

另修正：gate=reject 且后端未给 modulation 时，结论区原本只显示一个破折号，现改为"未识别"并使用报错色，与门控状态一致。

## 9. 需要后端配合或确认的点

1. **comparison 的键集要写进契约 v2**。契约第 2 节的示例只列了 cfo_error_hz / symbol_rate_rel_error / es_n0_error_db / sps_true / sps_est / modulation，但 spxh/core/estimate/analyze.py 的 compare_with_truth() 实际还产出 cfo_true_hz / cfo_est_hz / symbol_rate_true_hz / symbol_rate_est_hz / symbol_rate_error_hz / es_n0_true_db / es_n0_est_db 以及三个 confidence。前端两种形态都兼容，但契约应以后端实际产出为准补全。
2. **/api/features 必须下发 names 与 groups**，否则前端只能使用内置兜底目录；values_by_name 建议保留（前端已使用）。
3. **错误响应体固定为 {"error": "中文说明"}**，前端直接展示该文案；若不是 JSON，前端会截断显示原始文本前 180 字符并标注"响应不是合法 JSON"。
4. **/api/waterfall 的 magnitude_db 排列约定**请保持为"F 行（freqs 升序）× T 列（times 升序）"，前端按第 0 行=最低频画在底部。shape 字段前端只用于显示与校验。
5. **/api/spectrum 的 freqs 必须等间隔且升序**（前端按 fx0..fx1 线性映射画线），residual_db 必须与 psd_db 等长且已钳位到 [-60, 0]。
6. **载频口径**：前端把 cfo.value 当作相对基带的频偏（Hz）画在频率轴的该 Hz 处，与 peak.frequency_hz 同轴。如果后端将来改为输出绝对 RF 频率，需要同步改本页纵线口径。
7. **静态资源路由**：/ 返回 index.html，/static/ 返回静态文件，/static/mock/ 托管假数据（前端在 ?mock=1 时直接按 /static/mock/<slug>.<endpoint>.json 取文件，服务端只需普通静态托管，无需额外接口）。
8. 若后端希望前端调整请求参数默认值（当前：spectrum 用 nperseg=1024 / nfft=8192 / points=1200；waterfall 用 nperseg=min(nperseg,512) / max_frames=400 / max_bins=192；constellation 用 max_points=3000），告知即可，均在工具条或常量中集中可改。

## 10.8 本轮自查发现并修复的真实缺陷

1. **qpsk/bpsk 永远画不出判决区域**：`demodModKind()` 原来只用 `^([0-9]+)psk$` 匹配，而 qpsk / bpsk 没有数字前缀，于是返回 null、判决区域被静默跳过。已改为显式映射 **qpsk→4、psk/bpsk→2**，并对数字化制式校验"2 的幂 / 完全平方数"；同时给星座图加上"无判决区域模板"的显式提示，避免再次静默。冒烟场景 M 覆盖。
2. **同一端点在初始化时被请求两次**：`init()` 先 `activateTab(activeTab)`（带 ?tab=demod 时触发一次 /api/demod），随后 `loadPath()` 又重置代际并再请求一次，第一次结果被 dataGen 作废。已给 `activateTab` 增加 `skipData` 选项，init 阶段只负责显示面板，数据统一交给 `loadPath`。这不只修了解调页，也顺带消除了 features/classify 在带 ?path=&tab= 时的重复请求；场景 A33/G1 验证。
3. **超长数组会撑爆 DOM**：bits.preview / llr.sample 无长度上限，后端若给整段比特流会创建上千个节点。已加 1024 位 / 200 采样上限并在界面上明示截断；场景 N 验证。

另（测试侧，非产品缺陷）：假 DOM 的 `querySelectorAll` 不支持后代选择器（`.llr-bar i`），断言已改为按类计数；动态 `createElement` 出来的节点也已纳入类查询。

`drawFecCurves()` 在一块 Canvas 内画全部曲线：

## 11.5 数据流、缓存与 URL 同步

- 唯一新端点 `GET /api/fec`，**不带任何查询参数**（契约 §11）。它是一份**全局报告**，与当前案例路径无关。

## 11.8 本轮自查发现并修复的真实缺陷

1. **自动选址导致 `/api/fec` 被请求两次**。原先 `loadFec()` 复用 `loadDataset()`（受数据代际 `dataGen` 保护），而初始化流程里 `loadCases()` 成功后会自动选中第一个案例并 `loadPath()`——`loadPath()` 既重置 `state.pending`（丢掉在途标记）又 `dataGen++`（作废在途响应），于是 `ensureTabData('fec')` 认为"还没加载"又发一次请求。已改为：`loadFec()` 用自己的 `fecGen` 代际计数器（与 `dataGen` 解耦），`loadPath()` 保留在途的 `pending.fec`。S1 / S5 / S7 覆盖。
2. **译码页 BER/BLER 分段按钮会被频谱页的全局处理器误改**。频谱页用 `document.querySelectorAll('.seg-btn')` 绑定幅度刻度，译码页的分段按钮共用 `.seg-btn` 类名，点一下会连带把 `state.ui.scale` 置为 db、并重刷所有 `.seg-btn` 的 `is-active / aria-pressed`。已在处理器入口加 `if (!b.getAttribute('data-scale')) { return; }`（只有带 `data-scale` 的才是幅度刻度）。S2 / S6 覆盖。

## 12.3 相位模糊角（本页重点）

## 12.5 帧表 / 载荷 / 汇总卡 / warnings

- **帧表**读 `frames[]` 的 `index / start_symbol / start_bit / preamble_ok / header.payload_len / crc.ok / bit_errors_vs_truth`；前导与 CRC 用绿 ✓ / 红 ✗，CRC 单元格 title 附 `expected / computed`；`bit_errors_vs_truth` 为 null 时显示"无真值"（不再是字面 null）。行可点选（事件委托到 `#frame-table`），选中行加 `.is-sel`。
- **载荷面板**读选中帧的 `header{payload_len,modulation,fec,interleave,header_hex}`（外加 `crc` 行），以及 `payload`。HEX 每 16 字节一行分组、等宽；ASCII 不可打印字符为 .。**字段容错**：`payload.hex` 缺失时用 `payload.head` 前 32 字节拼 HEX，`payload.ascii` 缺失时从 HEX 自行生成（可打印 0x20–0x7E，其余为 .）；两者都没有时明写"该帧没有 payload.hex 也没有 payload.head"。
- **汇总卡**读 `summary`：帧数 / CRC 通过（k / n）/ 载荷字节 / 与真值逐字节一致；`payload_bytes_exact` 为 null 时显示"（无真值）"。
- **warnings** 逐条渲染；无告警显示"无告警"，数据未到时显示对应的 pending/failed 文案。

## 12.6 数据流、缓存、mock 兜底与 URL 同步

- 唯一新端点：`GET /api/frame?path=...&modulation=...`。前端**只发 `path` 与可选 `modulation`**（契约的 `symbol_rate / cfo` 由后端自行估计，前端不传，避免把 M1/M3 的估计值二次喂回）。
- `ensureTabData('frame')`：`!state.frame && !state.pending.frame && !state.failed.frame` 才请求——切走再切回不重复请求，失败后由「重新提取」或「重试全部」显式重试。
- 触发刷新：路径变化（`loadPath` 重置 `state.frame`）、调制下拉变化、「重新提取」按钮。
- 超时：`frame` 加入 `API_SLOW_TIMEOUT_MS = 90000`（帧同步是慢接口）。
- **mock 兜底**：`?mock=1` 时先读 `/static/mock/<slug>.frame.json`（slug 规则与既有 mock 一致）；若该文件 404，再读全局 `/static/mock/frame.json`。实现上给 `apiUrl/apiGet` 增加了可选 `mockFile` 参数（既有调用点不受影响），兜底逻辑在 `loadFrame(mockFile)` 内完成，第一跳 404 不记错误条。
- URL 同步：`?tab=frame` 由既有 `TABS/readUrl/syncUrl` 自动支持；`?mock=1` 与 `?path=` 不变。帧页调制**未单独写入 URL**（沿用解调页的 `mod` 语义会冲突）；若需要持久化，可加 `fmod`，成本很低。

## 13.3 统一图表交互层（`VIEWS` / `chartWindow` / `chartGeom`）

**不做"每图一套"**：所有 canvas 图共用一个 view 注册表与一组事件处理函数，图自己只声明四件事——
完整数据域、轴性质（是否对数）、数据点数、重绘函数。

```
chartWindow(id, {x0,x1,y0,y1}, {xLog,yLog,xCount,yCount,yZoom,fmtX,fmtY,unitX,unitY,canvas,redraw})
    → 返回当前窗口 {x0,x1,y0,y1}（原始单位，直接当 xmin/xmax/ymin/ymax 用）
chartGeom(id, m, pw, ph)   // 记录绘图区几何，滚轮/拖动的像素→数据换算要用
drawViewBadge(ctx, id, m, pw, ph)  // 缩放后在图内右下角画"当前范围"角标
```

**坐标约定（关键）**：窗口一律存 **显示坐标** —— 线性轴 = 数据值，对数轴 = `log10(数据值)`。
于是缩放/平移/钳制只有一套算术，对数轴天然按对数缩放，不需要任何 `if (log)` 分支。

**事件**（在 `chartBind()` 里一次性挂到 canvas 上，`v.bound` 幂等）：

| 操作 | 行为 |
| --- | --- |
| 滚轮 | 以鼠标位置为锚点缩放；二维图 X/Y 同时缩；**Shift 只缩 X**，**Alt 只缩 Y**；`deltaMode=1` 按 16 倍换算；`passive:false` + `preventDefault` |
| 按住左键拖动 | 平移；位移 > 3px 才生效（避免误触）；同时在 `document` 上挂 move/up |
| 双击 | 复位到完整数据域 |
| 右上角"重置视图"按钮 | 与双击等价；未缩放时静默（低对比），缩放后点亮为强调色，title 里带当前范围 |

**钳制**（`clampAxis`）：

- 最小跨度 = `max(8 个数据点跨度, 1e-3 × 原始跨度)`；当数据点太少导致"8 个点"反而大于原始范围时，退回 `max(1e-3×原始, 0.5×原始)`，保证还能缩；
- 最大跨度 = 原始范围（缩过头自动回到全量程，按钮随之回到静默态）；
- 平移后把窗口推回原始范围内（贴边停住），跨度保持不变。

**数据刷新自动复位**：`chartWindow()` 用完整数据域的签名（两端点 + 点数 + 对数标志）比对，签名变化即把窗口清空重来。
这样**不需要在每个 loader / 控件回调里手写 reset**：换案例、换 nperseg/nfft/points、切 dB↔线性、切 BER↔BLER、窗口 resize 都不会把上一份数据的缩放状态带过来。

**范围读数**：缩放后在图内右下角画一行小字（例：`X -1.2k…1.2k Hz, Y 0.0…2.0k Hz`），同时轴刻度本来就跟随窗口（`ticks(win.x0, win.x1, n)`）。
每张图的"重置视图"按钮 `title` 也带同一句话，便于 hover 查看。

## 13.5 对数纵轴的缩放（硬要求 A-4）

- **BER/BLER 曲线**：`yLog: true`。窗口存 `log10(y)`，所以"缩小一档"在数据上是**几何缩放**：
  `y1_new = y0 · (y1/y0)^(1/k)`。这保证了在 1e-6…1 这种跨 6 个数量级的轴上，每一档缩放看到的**十进制宽度相同**，而不是被线性拉伸。
  自测里用"线性预测值 vs 几何预测值"双向断言区分（见 13.9 S7）。
- **PSD 的 dB 轴**：dB 本身就是功率的对数刻度，窗口按 dB 线性收缩 = 功率按几何缩放，因此不需要再取一次 log；
  线性的"纵向相对变化量"（每像素多少 dB）随缩放同步变化，符合"不要线性拉伸对数轴"。
- **同步轨迹 / 剖面 / 热图**：Y 是线性物理量，按线性缩放。

## 13.6 容错与空态（SSCA）

- **失败态文案固定**：`sscaEmptyText()` 优先返回 **"谱相关加载失败（见顶部错误条）"**（failed）→"加载中…"（pending）→"等待数据…"（无 path）→ 具体空态文案。
  **不存在"永久停在加载中"**：`apiGet` 自带 25s/90s 超时（`API_SLOW_TIMEOUT_MS.ssca = 90000`），失败即置 `state.failed.ssca`，面板与状态条同步切换。
- **逐点容错**：`surface_db` 里的 `null` 按最暗色渲染（`t=0`），悬停时 tooltip 明确写 `null（无效点）`；行比列短、行缺失、`peaks` 为空、`peaks` 里字段缺失或非数，全部逐项跳过。
- **轴与数据维度不一致**：见 13.11 第 1 条 —— 优先用 `surface_freqs`/`surface_alphas`，退回 `freqs`/`alphas` 并按行数/列数截断，保证"轴长度 = 数据维度"。
- **剖面长度不一致**：`alpha_profile.alpha_hz` 与 `level_db` 取 `min` 并跳过非数点。
- **悬停**：`nearestIndex` 找最近的 (α,f) 采样点，tooltip 显示"α … Hz · f … Hz / SSCA 电平 … dB"，同时在图上画虚线十字；移出（`mouseleave`）即隐藏。
  拖动平移期间不弹 tooltip（`dragV` 守卫），避免和缩放/平移打架。

## 13.10 本轮自查发现并修复的真实缺陷

1. **FEC 图漏了 `chartGeom()`（真实 bug）**：`drawFecCurves` 只调了 `chartWindow`，没记录绘图区几何，于是 `v.m` 为 `null`，
   滚轮/拖动事件在守卫处直接 return —— **BER 曲线看起来"能缩放但点了没反应"**。冒烟 S7 第一次跑就抓到（"滚轮缩放后出现视图角标"失败），补上 `chartGeom('fec', m, pw, ph)` 后通过。
   教训：交互层的注册是**两个动作**（窗口 + 几何），少一个就静默失效，必须有一张"十张图全覆盖"的用例兜底。
2. **`state.ssca` 未在 `loadPath()` 里重置**：会重演 M5 帧页踩过的"换案例后显示上一案例数据 + `ensureTabData` 误判已有数据不再请求"。已补 `state.ssca = null; sscaHover = null;`。
3. **瀑布图/SSCA 热图共用离屏 canvas 会被互相清空**：`getOffscreen()` 是全局单例，瀑布(T×F) 与 SSCA(F×A) 尺寸不同，来回切页会把缓存位图重置成空白。
   已为 SSCA 单独建 `sscaOff`，并让缓存键同时校验尺寸。
4. **缩放后折线越出绘图区**：频谱/相关峰/同步轨迹/FEC 的折线在缩放后不裁剪会画到坐标轴外。已给每处折线加 `rect+clip`（星座与热图同理）。
5. **FEC 悬停十字线在缩放后可能画到框外**：补 `hoverX` 越界判断；同时拖动平移期间屏蔽 tooltip。
6. **初稿把"重置视图"按钮当成每图手写 DOM**：改为 `ensureResetBtn` 在第一次绘制时自动挂到 canvas 的父节点，避免 10 处重复代码与漏挂。
7. **悬停定位用了 `d.freqs` 而不是热图实际轴（真机数据下会错报 null）**：真机 `freqs` 有 256 项而 surface 只有 128 列，

   教训：**只要同一份响应里存在两套轴，凡是"把数据映射回坐标"的地方都必须用同一套轴**，画图和悬停不能各用各的。

## 14.3 帧页：帧头 CRC 三态与盲恢复块

**三态而不是两态**（这是本轮最容易踩的坑）：`frameHeaderCrc(header, frame)` 只在字段是布尔值时返回 true/false，缺失一律返回 `null`；表格里 `null` 渲染成 `—（旧格式）` 且用 `check-na`（灰），**绝不显示红叉**。只有 `false` 才是红叉。

**字段位置兼容**：契约 §15 把 `header_crc_ok` / `header_crc8` / `crc8_expected` 放在 `frame.header` 内；当前后端 `spxh/core/framesync/extract.py` 把它们放在**帧顶层**（`frames[].header_crc_ok`）。前端优先读契约位置、再回退帧顶层（`headerCrcField()`），两种真实响应都能显示。

**盲恢复块**：`frameBlind(d)` 取 `d.sync.blind`（对象）。顶层 `d.blind` 只在它**也是对象**时才兼容；当前后端把 `blind` 回传成布尔开关（`payload["blind"] = bool(blind)`），布尔被忽略、不会误显示成一块空盲恢复。显示内容：`header_crc_ok`、`length_recovered`（badge 三态）、`hypotheses_tried`、`repaired_header` 的 `payload_len`/`fec`/`interleave`（缺失逐项降级为 `—`）。

## 14.4 报告页：数据流 / 缓存 / mock 兜底 / URL 同步

- `loadNarrate(mockFile)`：`apiGet('narrate', { path, provider }, mockFile)` —— **走既有 apiGet（带 90s 超时），没有任何裸 fetch**；用 `state.dataGen` 代际守护，换案例后旧响应直接丢弃。

## 14.5 容错与空态

- **失败态固定文案**：`narrateEmptyText()` 优先返回 **「报告生成失败（见顶部错误条）」**（failed）→「加载中…」（pending）→「等待数据：请在左侧选择案例或输入路径」（无 path）→「暂无报告数据」。超时（90s）会让 pending 必然落地，**不存在永久停在加载中**。
- **逐字段容错，不崩**：
  - `sections` 缺失/为空 → 显示「报告没有 sections（sections 缺失或为空）」；

## 14.8 本轮自查发现并修复的问题

1. **帧头 CRC 字段位置与契约不一致（真实差异）**：契约 §15 放在 `frame.header`，后端 `extract.py` 放在帧顶层。初版只读 `header.header_crc_ok`，接真机（重启后）会全部显示「—（旧格式）」而看不出问题。已加 `frameHeaderCrc(header, frame)` / `headerCrcField()` 双向读取，并加 S5b 用后端真实形状兜底。

- `?mock=1` 下 `apiPost` 不发真实 POST，而是读 `/static/mock/llm_config.json` / `llm_test.json`；保存走 `mergeMockLlmConfig()` 做最小合并（含 `maskKeyHint()` 只留尾 4 位），便于离线演示。

## 15.6 保存语义：只提交改动，未输入密钥绝不提交 api_key

- `llmDiff()` 用 `baseline`（上次已加载/已保存的配置快照）逐字段比较，只把**改动过**的字段放进 body。
- `api_key`：**只有用户在输入框里真的输了新值**（`state.llm.apiKeyDraft !== ''`）才提交；留空绝不提交 —— 否则后端会把已保存的密钥覆盖成空串。这是本页最容易踩的坑，冒烟 S5/S9b/S10b 都做了断言。
- 没有任何改动且没点清除时**不发 POST**，直接提示「没有需要保存的改动（未提交 api_key，避免覆盖已保存的密钥）」（冒烟 S10a）。
- 成功：用响应（与 §17.1 同构、脱敏）整体刷新表单与 baseline，反馈「已保存 · LLM 已就绪/未就绪：… · config_path」。失败：`#llm-save-status` 显示后端返回的中文 `error`，同时进顶部错误条（冒烟 S6）。

## 15.7 测试连接 / 拉取模型 / 清除密钥

- 测试连接：`POST /api/llm/test`。不勾选「用当前表单值测试」时 body 为空 `{}`（用已保存配置）；勾选时带 `base_url` / `model` /（仅当输入了新密钥）`api_key`，属临时覆盖、不落盘。测试中 `#llm-test-result` 显示「测试中…（等待模型回应）」。`ok=false` 也返回 200，前端显示 `ok/latency_ms` 与「错误原因：…」（冒烟 S7/S7b）。
- 拉取模型：`GET /api/llm/models`。结果同时填充 `<datalist>` 与候选 `<select>`（空列表则下拉隐藏，手输不受影响）；`error` 非空显示「拉取失败：…」，`models` 为空且无 `error` 显示「接口返回 0 个候选模型」（冒烟 S8a/S8b）。测试连接返回的 `models` 也会并入候选。
- 清除密钥：按钮二次确认（`window.confirm`，文案含后果与不可撤销）；取消则**不发 POST**并提示已取消；确认后提交 `clear_api_key=true`（仍不提交 `api_key`）。环境拿不到 `confirm` 时按"取消"处理，绝不无确认清密钥（冒烟 S9a/S9b）。

## 15.8 报告页联动

- provider 下拉新增 `llm`，change 处理接受 `offline / llm / auto`；
- `syncNarrateProviderHint()`：配置未 ready（或未知）时，`#narrate-llm-hint` 显示「未配置 LLM，将使用离线渲染（LLM 未就绪：…）」，并给 `auto` / `llm` 两个 option 设置同义 `title` / `.opt-warn`；ready 时隐藏（冒烟 S11a/S11b）；

## 15.12 本轮自查发现并修复的问题

1. **空 body 的 POST 会把默认配置"物化"落盘**：联调时误发了一次 `POST /api/llm/config {}`，后端 200 并在 `models/llm_config.json` 生成了文件（`source` 从 default 变 file）。这会改变"配置优先级"的观测结果。前端因此**在没有任何改动时根本不发 POST**（`saveLlmConfig()` 里 `hasKeys(body)` 守卫），并在文档与代码注释里写清原因；同时手动删除了该次探测产生的临时配置文件，恢复 `source: default`。
2. **密钥框留空不能提交**：最初设想"全量提交也很省事"，但后端语义是"提交 `api_key` 就写 `api_key`"，留空即覆盖成空。已改为 `apiKeyDraft` 驱动、只有非空才提交，并用 S5/S9b/S10b 三条断言锁死。
3. **`confirm` 不可用的环境会静默清密钥**：`clearLlmKey()` 初版直接依赖 `confirm`。现在 `confirmDialog()` 在拿不到 `confirm` 时返回 false（视为取消），宁可不清也不无确认清除。
4. **`source` 是可选字段**：契约示例里 `source.enabled` 存在、真机也回传；但前端不能依赖它。角标对缺失一律「来源 —」，并且 `enabled` 缺字段按启用解释，避免旧版本后端导致误报"未就绪"。
5. **`SPXH_LLM_API_KEY` 环境变量双保险**：即使后端违反约定把值回显回来，`renderLlmEnv()` 也**只把它翻译成「已设置 / 未设置」两态**，永不上屏；S14 用哨兵值验证。
6. **报告页 provider 少 `llm` 选项**：旧代码 change 处理会把非 offline 一律压成 auto，新增选项后同步放宽为 `offline / llm / auto`，与契约 §17.5 对齐。
7. **重构 `apiGet` 时保留全部旧语义**：超时表、`{"error"}` 解析、mock 150ms 延迟、错误文案逐字保留；仅把 `/abort/i` 判定换成 `indexOf('abort')`（行为等价、避免测试脚本里的正则转义），并新增 `INFLIGHT` 去重（对旧页是净收益）。
8. **负面控制**：`--negative` 注入 1 条必失败断言，实测 exit=1、失败项正确列出，证明 186 条断言不是恒过。
9. **S14g 扫描器自检**：把哨兵明文手动注入 DOM 后扫描器确实能检出，证明"密钥不上屏"的断言真的在检查 DOM。

### 15.14.9 本轮自查发现并修复的问题

## 16.1 目标与信息层级

回答三个问题：**代理刚才做了什么？结论能不能信？为什么停下？**

1. **轮次时间线**（过程，本页重点）：每一轮的 `assistant_text` + 该轮每个工具调用的**工具名 / args / 耗时 ms / ok 状态 / 中文 summary**，失败调用整条标红并给出原因；
2. **最终结论**：`final.headline` 醒目 + `confidence` 数值条 + `sections[]`（标题 / 正文 / 证据表，证据表**直接复用报告页的 `narrateEvidenceTable()`**，样式与「报告」页同构）+ `uncertainties` + `next_actions`；

## 16.3 运行语义（有界、单发、不自动运行）

- **进入页面不发 POST**：`ensureTabData('agent')` 只调 `ensureAgentTools()`（一次 GET，工具清单 + budgets）。运行必须用户点「运行代理」（冒烟 S1：进入页面 POST=0，点击后 mock 读 `agent_run.json`）。
- 请求体严格按契约：`{path, goal, max_rounds, provider}`；`path` 为空时**不发请求**，直接进错误条提示。
- **超时不比后端早**：客户端 POST 超时 = `min(300, budgets.timeout_s) + 15` 秒（后端墙钟默认 120 s、上限 300 s），避免客户端先放弃。
- **进度不做假**：契约 §18 只有一次 POST，没有流式 / 轮询端点，所以前端**不伪造"第 N 轮"**；运行中 `#agent-status` 显示「运行中… 已等待 Ns · 最多 6 轮 · 最多 12 次工具调用 · 墙钟 120 秒」，由 500 ms ticker 刷新，且「运行代理」按钮禁用（`el.agentRun.disabled = true`）。轮数只有拿到响应后才知道，届时按真实 `rounds[]` 渲染「第 N 轮」。
- 用 `state.agent.gen` 代际号守护在途运行：换路径 / 重新运行会作废旧回调，避免旧案例的结果覆盖新页面。

## 16.4 `stop_reason` 六态中文解释

`#agent-stop` 徽标按语义着色（final=绿、max_rounds/max_tool_calls/timeout=琥珀、llm_error=红、no_llm=虚线灰），`#agent-stop-text` 给出解释：

| stop_reason | 文案 | 徽标 |
| --- | --- | --- |
| `final` | final：模型自己认为已经收尾，正常结束 | badge-hi |
| `max_rounds` | max_rounds：轮次预算用尽，被迫停止（结论可能还没收敛） | badge-mid |
| `max_tool_calls` | max_tool_calls：工具调用预算用尽，被迫停止 | badge-mid |
| `timeout` | timeout：墙钟超时，循环被中断（已完成的轮次仍然有效） | badge-mid |
| `llm_error` | llm_error：LLM 调用出错，循环提前终止 | badge-lo |
| `no_llm` | no_llm：没有可用 LLM，走了离线确定性计划（analyze → classify → frame → ssca） | badge-na |
| 其它 / 缺失 | 未知 stop_reason：X（前端原样显示，不猜语义）/ stop_reason 缺失：后端未给出停止原因 | badge-na |

离线（`mode=offline`）时在时间线上方额外显示「离线确定性计划（没有可用 LLM）」。

## 16.5 grounding 与 warnings

- `grounding.grounded === true`：`#agent-grounding-chip` 绿「grounded=true」，kv 行列出 `checked_numbers` / `unsupported` 条数。
- `grounded === false`：徽标红「grounded=false」，并在 `#agent-unsupported` 里把每个 `unsupported` 数字**逐条醒目列出**（琥珀底、描边、等宽）；空数组时显示「unsupported 为空 —— 后端未给出具体数字」（不假装已解释）。
- `grounding` 整体缺失：显示「响应没有 grounding：本次结论未做数字锚定校验」，不崩、不误报 grounded。
- `warnings` 非数组 / 缺失 → 0 条「无告警」；每条原样上屏（含"同工具同参数重复调用被拒绝"这类后端告警）。

## 16.11 本轮自查发现并修复的问题

1. **单发 POST 没有流式进度，差点做成假进度**。最初的"第 N 轮…"文案无法由任何端点支撑（`/api/agent/run` 一次返回）。改为"已等待 N s + 预算上限"，把"第 N 轮"留到真实 `rounds[]` 回来后显示；宁可少说，也不显示假进度。
2. **401 不能把响应体拼进错误文案**。后端 401 body 是 `{"error":"需要访问令牌（401）"}`，虽然当前不含敏感数据，但一旦有人把带 `Authorization` 的请求回显就会顺错误条泄漏。`apiCore` 因此对 401 使用**固定文案**，不拼响应体，并单独标 `.is-auth` + 「去设置」按钮。
3. **令牌初始化回填输入框会造成"令牌落 DOM"**。改为启动时只把令牌读进内存（`state.auth.token`），输入框保持空；用户要换令牌就粘贴新的。保存后立刻清空输入框。扫描器自检防止"恒过"。
4. **换路径必须作废在途运行**。加 `state.agent.gen` 代际号，`loadPath()` 自增并清 state；否则旧案例的响应会写进新页面（与 12.8 的 `state.frame` 同类坑）。
5. **未知 `stop_reason` 不猜**。契约只有 6 个取值，但前端对未知值原样显示 + 显式标注「未知」，避免把新语义错误翻译成既有文案。
6. **失败调用的原因字段可能不在 `summary`**。真机 tool_call 带 `error`（离线时为空串），前端在 summary 之外额外渲染非空的 `error`/`reason`，并保证空串不产生空行。
7. **假 DOM 的降级**：`%TEMP%` 写入被沙箱拒绝（EPERM），按任务约定把脚本临时放仓库根，跑完立即删除并 glob 复核不存在；未把测试脚本留在仓库。
