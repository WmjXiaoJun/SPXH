## 三、三平台差异化对照

| 维度 | 知乎 | 抖音 | 视频号 |
|---|---|---|---|
| 内容形态 | 长文 + 配图 | 竖屏 75 s 短视频 | 竖屏 120 s 短视频 + 图文 |
| 受众 | 工程师 / 学生 / 通信算法 | 泛科技 / 科普 | 职场 / 工程技术 / 泛科技 |
| 钩子 | "四不知"的场景 | 前 3 秒悬念 | 真实工作痛点 |
| 核心爽点 | 数据可复现、边界诚实 | "从看不懂到读出来"的视觉过程 | "每一步都有依据"的可信感 |
| 节奏 | 慢，可跳读 | 每 4~6 s 换画面 | 每 8~12 s 换画面 |
| 封面 | 16:9 横版 | 3:4 竖版 | 9:16 竖版 |
| 结尾引导 | 项目地址 + 欢迎挑错 | 链接在评论区 | 链接在评论区 |

**推荐发布顺序**：知乎长文先发（沉淀搜索流量）→ 隔 1~2 天发抖音（引流）→ 视频号紧随（信任转化）。
三个平台的评论区都置顶同一条项目地址，互相导流。

## 四、发布前必做的 3 件事

1. **替换 GitHub 占位符**：三篇文案和评论区模板里的 `https://github.com/WmjXiaoJun/SPXH` 都是占位地址，发布前换成真实仓库链接（README 里也是同样的占位符）。
2. **脱敏检查 ⚠️**：工作台截图右上角/时间线里包含本机绝对路径，例如
   `D:\BaiduSyncdisk\wmj_work\SPXH\data\demo\...`（主要在 **11-代理-LLM时间线** 这张最明显）。
   如果不希望公开目录结构，发布前把该区域裁掉或打码；其余截图基本不含个人信息。
3. **别用"最/第一/绝对"这类词**：项目本身主打诚实边界，文案里也刻意没写"业界最强"这类表述，短视频标题同样建议保持具体承诺（"从看不懂到读出来"），转化反而更好。

## 五、一键重拍截图

```bash
python -m spxh serve                       # 先启动工作台（默认 http://127.0.0.1:8760/）
pip install playwright                     # 若未安装
python "docs/发布/工具-截图.py"             # 默认拍 11 个页签，输出到 docs/发布/配图/
```

脚本用真实浏览器（Playwright + Chrome）打开工作台，按页签逐个截图，代理页会自动点「运行代理」并等到跑完再拍。

## 六、素材真实性说明

- 所有数字均来自项目自带验收报告（`docs/M0~M12-验收报告.md`），可用 `python scripts/check_*.py` 复跑；
- 「报告」和「代理」两张 LLM 截图是真机运行结果（deepseek-flash，走用户本机已配置的 key），不是合成示意；
- 「报告」页顶部那条黄色告警是真实的降级提示（模型某次输出不符合 JSON 契约，平台如实告警而不是假装成功）——长文里把它当作"连失败路径都诚实"的例子来讲，是加分项，不必删。
