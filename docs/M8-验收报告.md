## 2. RS 误差 + 擦除联合译码

**能力**：2 x 未知错误数 + 擦除数 <= nsym = 2t。RS(76,60) 时 t=8、nsym=16，
所以 (16 擦除) / (8 错误) / (4 擦除 + 6 错误) 都能纠 —— 关键是最后这类：
**擦除位置标得不全、还剩几个未知错误**，纯擦除译码只能放弃，联合译码能救回来。

| 场景 | 2f+e | 结果 |
|---|---|---|
| 8 个未知错误 | 16 | 纠正 8 个，还原 ✓ |
| 2 擦除 + 7 错误 | 16 | 纠正 9 个，还原 ✓ |
| 4 擦除 + 6 错误 | 14 | 纠正 10 个，还原 ✓ |
| 8 擦除 + 4 错误 | 16 | 纠正 12 个，还原 ✓ |
| 16 擦除 + 0 错误 | 16 | 纠正 16 个，还原 ✓ |
| 4 擦除 + 7 错误 | 18 | **如实报不可纠** ✓ |

做法：先由擦除位置构造擦除定位多项式 Gamma(x)，用 Forney 伴随式把擦除从方程里除掉，
再对剩下的部分跑 BM 得到"未知错误"定位多项式，乘回去做 Chien 搜索与 Forney 求幅值，
最后仍然用"伴随式必须全零"做硬判据（超出能力一律报不可纠，绝不猜）。

### 期间修掉的两个真 bug

1. **擦除定位多项式的系数顺序**：低位在前的表示下 prod(1 + X_p x) 的系数数组是 [1, X_p]，
   一开始写成 [X_p, 1]（= prod(x + X_p)，是另一个多项式），Chien 搜索一个根都找不到。
2. **Forney 伴随式的用法**：T(x) = [S(x)Gamma(x)] mod x^nsym 不能整段喂给 BM ——
   低位那几项里擦除的贡献还没抵消干净，BM 会解出虚假的"错误定位多项式"
   （实测 16 擦除 + 0 错误时 BM 给出 8 次多项式）。正确做法是只喂 **i = e .. nsym-1** 那一段。
3. **边界**：擦除数用满 nsym 时没有剩余伴随式可用，退化为纯擦除（位置已知只解幅值），
   这条路径单独保留，否则 16 擦除这种极限情形会被误判为不可纠。

## 3. SSCA 谱相关（可解释性）

原理：通信信号循环平稳，自相关随时间周期变化，于是在"频移 f / 循环频率 alpha"平面上有结构：
成型脉冲的信号在 alpha = 符号速率及其谐波处成脊，载频偏移体现在 f 轴上。
白噪声没有这种结构（只在 alpha = 0 有能量）。所以这张图本身就是"为什么这么判"的证据。

实现：条带谱相关（SSCA）。把信号切成 K 个 L 点帧、加 Hanning 窗做 FFT，取
S_x^alpha(f) = (1/K) sum_k X_k(f + alpha/2) conj(X_k(f - alpha/2))，
alpha 取 fs/L 的整数倍，边缘无效区标 null（不假装有值）。

实测（QPSK / 2FSK，Rs=1000 Hz，CFO=120 Hz，20 dB，nfft=256）：

| 特征 | 谱相关给出 | 真值 | 说明 |
|---|---|---|---|
| 符号速率 | **1000.0 Hz** | 1000 Hz | alpha 轴峰，分辨率 fs/nfft = 31.25 Hz，正好命中 |
| 载频偏移 | 124.3 / 120.4 Hz | 120 Hz | alpha != 0 脊线的 f 位置，一个 bin 之内 |

两个踩坑：

1. **alpha 轴尺度差 2 倍**：SSCA 里两路频谱各偏 alpha/2，所以 bin 位移 shift 对应
   alpha = 2 x shift x 分辨率；写成 shift x 分辨率会把符号速率读成一半（实测 500 Hz vs 1000 Hz）。
2. **CFO 不能用 alpha=0 那一行取峰**：那是普通功率谱，而 RRC 成型谱是**平顶**的，
   峰值/重心都会被平坦区带偏（实测偏 30~60 Hz，和 M1 当年"平顶谱 argmax 没用"是同一个教训）。
   改用 alpha != 0 脊线的位置后，误差落进一个 bin。
   分辨率限制决定了它只能作**解释**用 —— 精确估计仍由 M1 给（< 1% Rs），
   接口里同时返回 features（谱相关）与 estimate（M1），前端并排显示供对照。

前端的案例列表会直接列全，SSCA / 解调 / 帧页都能用它们做对照。

**一个如实记录的边界**：编码链路的可用性受 M3 同步/解调限制 —— QPSK 的编码案例都能满帧还原，
但 8PSK/16QAM 的编码案例（前导只有 4/3 个符号、M3 在高阶调制上本来就有误码地板）
在 6~12 dB 仍然一帧都锁不住。这不是译码的问题，是"短前导 + 高阶调制 + 中等信噪比"的组合问题，
正是下一轮"更强前导"要解决的。

## 5. 本轮**没做**的两项（如实说明）

1. **帧头自身短 CRC 未做**：这是**线格式变更**（帧头从 4 字节变 5 字节），
   会同时影响合成器、解析器、盲搜索、既有 demo 数据与多个验收脚本的期望值。
   做完它才能让"载荷长度也被打错"的情形可盲恢复（现在盲搜索覆盖 (编码, 交织)，不含长度）。
   做法已经想清楚：帧头加 1 字节 CRC-8，盲搜索先按 CRC-8 过滤长度假设（<= 2048 字节）
   再做帧 CRC 校验；代价是候选空间从 10 涨到约 2 万个"帧头级"检查（不做译码，很快）。
   下一轮第一项。
2. **更强前导只做了一半**：候选峰预算从 12 提到 40、阈值降到 0.35 x 峰值（M7 已生效，
   8 dB 的编码案例从 0 帧变成能解析）。但 5~8 dB 的解析率问题仍在（24 帧里只解析出 9~17 帧）。
   下一步要么用更长前导（Barker-13 重复），要么做跨帧相干/非相干积累 —— 两条都要动帧结构或同步器。
