# SPXH 智能射频信号分析平台 — 实现方案 v0.1

> 来源：微信公众号文章《拆解｜从一段未知 I/Q 数据到可读出的业务比特：一套智能射频信号分析平台的完整链路》（【射频信号分析实战】专栏 第 1 期，2026-10-02）
> 本文档把该文章当作**需求规格书**使用：它的"是什么/为什么"写得清楚且合理，但**没有给出可验证的实现细节、数据集与实测指标**（文末"代码链接"实际指向知识星球 219 元/年 与 面包多付费页）。因此本方案在复刻其链路的同时，补齐它省略的工程环节。

## 0. 目标与验收口径

**目标**：输入一段未知 I/Q 录波（无任何先验），输出可读业务比特，并给出每一步的判断依据、置信度与人工可覆盖的入口。

**验收硬指标**（必须可量化、可复现）：

| 层级 | 指标 | 判据 |
|---|---|---|
| 参数估计 | 载频偏差、符号速率相对误差 | CFO 不超过符号速率的 1%；符号速率相对误差不超过 1e-3（16QAM 的 EVM 大致从此开始明显劣化）|
| 分类 | 六类混淆矩阵、各类召回率 | 合成集 SNR 不低于 0 dB 时总体不低于 95%，并给出每类召回 |
| 置信度 | 可靠性图 / ECE | 门限由校准后概率决定，OOD 检出率可报 |
| 解调译码 | BER vs Eb/N0 | 能复现"软判决比硬判决约 2 dB 增益"这一结论 |
| 端到端 | 帧通过率（CRC 通过） | 合成信号全链路：SNR 不低于 6 dB 时不少于 99% 帧 CRC 通过 |
| 可复现 | 同参数同输入两次运行 bit-exact 一致 | 全局 seed + 参数快照 + 中间结果归档 |

**总设计原则**：链路做成"每一级都是纯函数 + 显式参数 + 证据输出"的流水线，任一参数可人工覆盖后从该级重跑，且全部中间结果可归档回放。

## 1. 架构

### 1.1 分层（比文章更明确的接口约定）

    spxh/
      core/
        io/        # RAW(f32/i16) / WAV / SigMF 读写 + 采样率自动识别
        synth/     # 六类调制 + 损伤注入 + 真值 sidecar（最关键的基础设施）
        dsp/       # 复数基带、滤波、Welch、STFT、重采样、AGC/IQ 校正
        estimate/  # CFO、符号速率、信噪比、定时相位
        features/  # 五域 23 维 + 特征选择
        classify/  # RF 分类器 + 概率校准 + 置信度门控 + 物理规则回退
        demod/     # 匹配滤波、定时同步、载波恢复、判决/LLR
        interleave/# 矩阵块交织、卷积交织及其逆
        fec/       # Viterbi(硬/软)、RS(GF256)、CCSDS 级联、LDPC(Log-SPA)
        framing/   # Barker-13 同步、帧头解析、CRC-16-CCITT
        explain/   # SSCA、星座解释、洞察清单（自然语言模板）
        pipeline/  # Stage 协议、缓存、脏传播、参数快照
      app/         # GUI（后置）
      cli/         # 批处理、基准扫描、参数网格
      tests/       # 单元对拍 + 端到端网格 + 回归快照
      data/        # 合成集、golden 集、标注

### 1.2 Stage 协议（核心抽象）

    @dataclass(frozen=True)
    class StageParams: ...            # 全部可 JSON 序列化
    class Stage(Protocol):
        name: str
        def run(self, sig, params, ctx) -> StageResult   # result.signal / result.evidence / result.metrics
        def explain(self, result) -> list[str]           # 人类可读结论
        def fallback(self, sig, ctx) -> StageResult|None # 确定性回退路径

- ctx 携带：采样率、全局 seed、上游估计结果、版本号。
- 中间结果落 HDF5/JSON sidecar，参数变了只重跑下游（脏传播）。
- **禁用隐式全局状态**：所有估计值只能来自 ctx，不能从 GUI 控件直读。

## 2. 里程碑（每个都有可验证出口）

### M0 骨架 + 合成数据闭环（1–2 周）★ 最先做，最重要
- IO：RAW f32/f64、i16、WAV、SigMF(.sigmf-meta/.sigmf-data)。
- 合成器：BPSK/QPSK/8PSK/16QAM/2FSK/4FSK；参数：SNR(−5…+35 dB)、CFO、相位噪声、滚降 α、编码方式、交织深度与参数、载荷内容、**帧结构**。
- 输出同时写"真值 sidecar"：每个符号/比特、帧头位置、CRC 通过标记。
- 出口：CLI 一条命令生成数据集；任何后续 stage 都能用真值算误差。
- **判据**：没有真值就没有验证。这一步不做，后面所有"调参"都是盲调。

### M1 频谱/时频/参数估计（2 周）
- Welch 功率谱（峰值频率、占用带宽、噪声底）、STFT 瀑布。
- CFO：谱峰 + 门限粗估 → Rife–Boorstyn / 相位差精估；对 FSK 用瞬时频率中心。
- 符号速率：包络谱线法 + 循环平稳 α 切片，两法交叉验证并输出置信度。
- SNR 估计（M2M4 / 谱方法），供 LLR 计算使用。
- 出口：estimate → EVM 因果曲线（故意注入估计误差，看星座如何旋转/模糊）。文章第 8 章结论 1 的量化验证就在这里。

### M2 特征工程 + 分类 + 门控（2–3 周）
- 五域 23 维：累积量 C40/C42/C63/C80、谱特征（能量分布/谱峰度）、STFT 时频动态、星座域（EVM/聚类数/离散度/展宽/旋转）、循环平稳强度。
- 特征选择：方差阈值 + 相关性剪枝（保序、可复现）。
- 分类：RandomForest + 交叉验证；**概率校准**（Platt/Isotonic，或 predict_proba + 温度标定）。
- 门控：门限不写死 70%，改为"按目标误判率取校准后概率分位点"；叠加 OOD 检测（特征空间马氏距离 / IsolationForest），因为 max-softmax 对分布外数据过度自信（文章第 8 章结论 5 提到了现象，但没给方法）。
- 物理规则回退：累积量理论边界（|C40| 等对 PSK/QAM 的判决域）+ 瞬时频率分布（FSK 阶数）；穷举式确定性搜索，**结果必须可复现**。
- 出口：混淆矩阵 + 可靠性图 + OOD 测试（用未参与训练的 32QAM/GMSK/MSK）。

### M3 解调 + 同步（3 周）
- **文章漏掉但必须补**：定时同步与载波恢复。
  - 匹配滤波（RRC，α 与发端一致）→ 定时误差检测（Gardner/Mueller–Müller）+ Farrow/多相插值重采样。
  - 载波恢复：PSK 用 Costas 环 / 判决导向；16QAM 用 DD 或 CMA 盲均衡对抗 ISI；连续相位与残余频偏用二阶环跟踪。
  - AGC、DC 偏置、IQ 不平衡校正（非合作接收的真实数据里这些不修，分类和 EVM 全都会崩）。
- 判决：PSK 扇区切片、QAM 双阈值网格、FSK 鉴频切片（与文章一致）。
- **软判决接口**：解调阶段输出每比特 max-log LLR（需要正确的星座标定与噪声方差），供 Viterbi/LDPC 使用。这是文章一笔带过、实践中最容易翻车的地方。

### M4 解交织 + 信道译码（4–6 周，最重）
- 解交织：矩阵块 + 卷积交织逆运算（参数由 ctx 传入）。
- Viterbi：K=7、r=1/2、(133_8,171_8)，硬判决 + 软判决两条路径（同一网格实现，判决度量可切）。
- RS：GF(2^8)，Berlekamp–Massey + Chien + Forney，支持纠错上限与"不可纠正"显式标记。
- CCSDS 级联：内 Viterbi + 外 RS，按 CCSDS 131.0-B 的 TM 帧与交织深度（I=1/2/4/5）实现；不可纠正块必须向上报告，不得静默输出。
- LDPC：Log-SPA 最小和 + 分层调度；支持 3GPP TS 38.212 (NR BG1/BG2) 与 ETSI EN 302 307 (DVB-S2)。
- 出口：BER 曲线 vs 理论界；能复现约 2 dB 软判决增益（文章第 8 章结论 3）。

### M5 帧同步 + 载荷 + CRC（1 周）
- Barker-13（1111100110101）滑动相关 + 归一化阈值 + 多峰消歧；给出同步位置与相关峰/旁瓣比。
- 32 位帧头（包标识/长度/标志）解析、MSB-first 打包、CRC-16-CCITT(0x1021) 校验。
- 载荷四视图：十六进制转储、安全 ASCII、原始二进制、遥测字段。
- 出口：端到端帧通过率曲线；文章第 8 章结论 4（无 CRC 不采信）落成代码断言。

### M6 可解释性 + 分析员工作台（2–3 周）
- SSCA 双频平面 S(f,α)（strip SSCA，O(N log N)，不要全平面暴力）；色标分区（黄白/橙/紫/深蓝）与循环熵。
- 可解释星座：聚类数/离散度/展宽/EVM/旋转 → **四段式模板**（观察到什么 / 意味着什么 / 可能原因 / 对译码的影响）。v1 用规则+模板，不要一上来就上 LLM。
- 洞察面板：绿/黄/红检查清单。
- 分析员工作台：任意 stage 参数覆盖 → 从该级重跑 → 前后对比。
- 标注与基准扫描：批量网格跑分，产出报告（CSV/HTML）。

### M7 加速与批处理（按需）
- 多进程/Dask 并行；SSCA/LDPC/Viterbi 的 Numba/Cython/Rust 化；如要实时，再考虑 GPU/FPGA。

## 3. 工程坑清单（文章没写、但我们一定会踩）

1. **盲编码参数**才是真难点：生成多项式、码率、交织参数未知时，Viterbi/RS 无从下手。v1 允许人工指定，v2 用"CRC 通过率/译码置信度"作为目标函数做小规模启发式搜索——这是很实在的"盲识别"落地口径。
2. **解交织先查**（文章结论 2 是对的）：建议在 pipeline 里做 A/B 对照实验，把"跳过解交织"直接做成一个可开关的失败演示。
3. **置信度门限要有依据**：70% 是拍脑袋值；改为校准 + 目标误判率分位点，并记录门限推导过程。
4. **幅度/相位标定**：16QAM 的判决门限与 LLR 都依赖准确幅度；先估幅度再判决。
5. **数值稳定性**：LDPC 用对数域（文章正确）；RS 的伽罗华域查表要一次性建好；Viterbi 用整数度量避免浮点漂移。
6. **频率与采样率假设**：WAV/RAW 没有采样率元数据时必须让用户显式指定或从 SigMF 读；自动识别不可靠。
7. **非合作场景缺项**：多普勒变化率、突发/跳频信号（文章提到 STFT 能看，但链路里没有突发检测与分段处理）、多径（需要均衡）。
8. **可复现性**：全局 seed、BLAS 线程数固定（OMP_NUM_THREADS=1 才能 bit-exact）、版本号写进 sidecar。

## 4. 对原文章的判断（信什么 / 别照抄什么）

**合理可信的部分**：
- 分层解耦、"ML 判别 + 置信度门控 + 物理规则回退"三层容错结构 —— 思路正确且工程上值得照抄。
- 用合成数据做单一损伤隔离测试（第 8 章结论 6）—— 这是全文最有价值的一条工程建议。
- CRC 闭环、"译码器输出 ≠ 正确比特" —— 正确。
- 软判决约 2 dB 增益、解交织对纠错码的必要性、SSCA 在极低 SNR 下仍能显示周期结构、Barker-13 自相关旁瓣不超过 1（主瓣:旁瓣 = 13:1）—— 都是教科书结论，正确。
- 选随机森林而非深度网络（低延迟、可快速重训、能出概率）—— 对六类任务是合理权衡。

**需要注意/存疑**：
- 全文**没有任何实测指标**：没有 BER、混淆矩阵、时延测量条件、数据集来源；"推理延迟 5 ms 以内"没有硬件与特征维数前提。
- "30 项功能"是功能点计数，不等于技术深度；六类调制是 AMC 的经典基准集，随机森林在合成数据上做到 90% 以上不稀奇。
- 文章自己承认的局限（第 9 章）恰好就是真实难点：编码参数盲识别、高阶 QAM/扩频/多载波、实时性。
- 省略了定时同步、均衡、IQ 不平衡、AGC、盲 SNR 估计、突发检测等**真实系统最容易失败的环节**。
- 引用 CCSDS 2011 Blue Book 已过时（现行为 131.0-B-3）。
- 商业属性：文末"代码链接"指向知识星球（219 元/年）与面包多，且文中"了解更多"跳转到的是《名誉保护投诉指引》页面 —— 无法据此验证其实实现。**当作需求书，不当作技术报告。**

## 6. 建议的执行顺序（结论）

1. **先做 M0（合成器 + 真值闭环）与 M1（参数估计）**：1–2 周内就能量化"符号速率/载频估计误差 → EVM"，把文章第 8 章结论 1 变成可测事实。
2. **分类阶段先上 RF 基线，但必须同时做概率校准与 OOD**，否则门控形同虚设。
3. **译码层按 Viterbi + RS + CCSDS 级联 走主线**（这是文章的主线，也最容易出可验证的 BER 增益）；LDPC 单独立项，别混在一起。
4. **GUI 最后做**：先用 CLI + HDF5 中间结果把链路跑通、跑准，GUI 只是把它包起来。
5. 全程维护一个 **golden 数据集 + 回归快照**，保证"人工覆盖参数后重跑"不会悄悄改变其他结论。
