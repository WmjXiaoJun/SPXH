### 9.8 CI 抓到的真 bug：matplotlib 未声明（2026-10-07）

仓库推上 GitHub 后，CI 在 **windows-latest 与 ubuntu-latest 两个平台同时失败**：

```text
FAILED tests/test_cli_m1.py::test_analyze_command_plot
ModuleNotFoundError: No module named 'matplotlib'
```

根因：CI 装的是 `.[dev,ml]`，而 `pyproject.toml` 的 extras 里**根本没有 matplotlib**，
可 `tests/test_cli_m1.py` 的 `--plot` 用例又必须用到它。README 第 4 步正是教用户
`pip install -e ".[dev,ml]"` 之后跑 `python -m pytest -q` —— 也就是说**任何人照 README 做都会挂**。
本地没暴露，是因为开发机的全局环境里早就装了 matplotlib。

修法（三处，互相配合）：

| 文件 | 改动 |
|---|---|
| `pyproject.toml` | 新增 `plot = ["matplotlib>=3.7"]`；`ml` 补上 `joblib>=1.3`（模型持久化实际要用） |
| `.github/workflows/ci.yml` | 安装改为 `.[dev,ml,plot]`，让出图用例在 CI 上真实执行 |
| `tests/test_cli_m1.py` | 用例开头 `pytest.importorskip("matplotlib")`，与 README「缺失时跳过出图，不影响判据」的承诺一致 |

同时把 README 中英文、CONTRIBUTING、requirements.txt、发布文案里的安装命令统一为 `.[dev,ml,plot]`。

**两条路径都实测过**：本地有 matplotlib → 用例正常执行并通过；用 `sys.modules['matplotlib']=None`
模拟缺失 → 用例被 **SKIPPED**、pytest **exit 0**（不再误报失败）。

### 9.9 Windows CI 的第二个坑：cp1252 编码（2026-10-07）

修掉 matplotlib 之后 ubuntu 全绿，**windows 改成在 `README numbers traceable` 这一步失败**：

```text
UnicodeEncodeError: 'charmap' codec can't encode characters in position 7-13
  File "scripts/check_readme_numbers.py", line 51, in main
    print("README 数字溯源：抽查 {} 行，命中 {} 行".format(checked, hit))
```

根因：GitHub 的 windows-latest 是 **en-US**，Python 在输出被重定向时使用 `locale.getpreferredencoding()` = **cp1252**，
打印中文直接抛异常。中文 Windows 是 cp936、恰好能编码，所以本机与作者机器都不暴露 ——
**这类问题只有跨平台 CI 才抓得到**，这正是把 CI 跑起来的意义。

修法（新增一个共享工具 + 所有中文输出入口调用）：

| 文件 | 改动 |
|---|---|
| `spxh/console.py` | **新增**：`ensure_utf8()` 把 stdout / stderr 切到 UTF-8；`SPXH_NO_UTF8=1` 可关闭；任何失败都静默放过（绝不因编码问题让程序崩） |
| `spxh/cli/main.py` | `main()` 开头调用 `ensure_utf8()` |
| `scripts/*.py`（12 个） | 在 `sys.path` 引导之后调用 `ensure_utf8()`（`check_readme_numbers.py` 顺带补上了缺失的 `sys.path` 引导） |
| `.github/workflows/ci.yml` | job 级 `env: PYTHONIOENCODING: utf-8` 再兜一层 |

**验证方式**（本机就能复现 CI 的条件）：把 `PYTHONIOENCODING` 设成 `cp1252` 再跑 ——
`scripts/check_readme_numbers.py`、`scripts/check_m0.py`、`python -m spxh --help` 在修复前都会 `UnicodeEncodeError`，
修复后三者 **exit 0 且中文输出正常**。
