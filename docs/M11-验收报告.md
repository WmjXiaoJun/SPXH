## 2. 工具调用代理

**分工**：模型决定"下一步看什么"，平台决定"能看多少"。工具是确定性管线的薄封装：

| 工具 | 作用 | 证据落点 |
|---|---|---|
| analyze | M1 参数（Es/N0、载频、符号速率 + 置信度） | signal |
| classify | M2 制式、门控、OOD | classification |
| spectrum | Welch 谱与谱峰 | extra |
| demod | M3 锁定状态、符号数、EVM、BER | extra |
| frame | M5 同步、帧头 CRC、载荷、盲恢复 | frame |
| ssca | M8 谱相关（alpha 峰 / 脊线） | cyclostationary |
| cases | 案例清单 | extra |

**三条硬约束**（这是"能用"和"危险"的分界线）：

1. **有界**：轮数（默认 6 / 上限 12）、工具调用次数（默认 12 / 上限 24）、墙钟（默认 120 s / 上限 300 s）
   任一触顶立即停止，`stop_reason` 如实回报（final / max_rounds / max_tool_calls / timeout / llm_error / no_llm）；
2. **同一工具 + 同一参数重复调用直接被拒**（模型空转烧钱是最现实的失败模式）；
3. **事实只能来自工具**：最终报告要过"数值落地检查"，白名单就是**模型实际看到的那份工具 JSON**
   （`evidence.shown`）—— 所以"编数"一定会被标出来。

**没有 LLM 也能跑**：离线确定性计划 analyze -> classify -> frame -> ssca，结构与 LLM 模式完全一致，
`mode=offline`、`stop_reason=no_llm`。面板永远有东西看，代理逻辑也能在没有 key 的环境里做回归。

**实测（真机 DeepSeek）**：3 轮、6 次工具调用、12.2 s，模型自己先去拿参数与谱相关，
再交叉核对"alpha 峰 1000.0 Hz vs M1 精确估计 1000.036 Hz"，然后看帧结构与 EVM，
最后给结论时**数字全部可溯源**（`grounded=true`）。这正是"代理"相对"一次性总结"的价值。

## 3. 访问令牌

| 场景 | 行为 |
|---|---|
| 只监听 127.0.0.1 且未设置令牌 | **不鉴权**（本机单人使用不该被令牌烦） |
| `--token <值>` / `--token auto` / 环境变量 SPXH_WEB_TOKEN | 所有接口需 `Authorization: Bearer <token>`（也接受 X-SPXH-Token） |
| 监听非回环地址但没设令牌 | **一律拒绝**（不能把密钥管理端点裸奔在局域网上） |
| /api/health、/api/auth/status | 永远开放（探活 + "我要不要令牌"） |

`GET /api/auth/status` 回报 `auth_required / loopback_only / hint`，前端据此提示。
实测（真起服务）：探活 200、auth/status 200、无令牌访问 /api/llm/config -> **401**（中文提示）、
带正确令牌 -> 200。

## 4. 密钥加密落盘（DPAPI）

- Windows 上用 **CryptProtectData**（绑定当前 Windows 用户）加密，配置文件只存 `api_key_enc`；
- **老配置自动迁移**：加载时发现明文 `api_key` 且 DPAPI 可用 -> 静默加密回写。实测：
  迁移前字段 `[api_key, base_url, model]` -> 迁移后 `[api_key_enc, api_key_protected, base_url, model]`，
  密钥仍可用（hint `****aa35`），**文件里连 `sk-` 前缀都搜不到了**；
- DPAPI 不可用/失败：退回明文并在接口里标 `api_key_protected: false`（**不假装已加密**），有单测覆盖；
- 接口行为不变：依然只回显尾 4 位。
